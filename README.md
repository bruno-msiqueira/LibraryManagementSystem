
# Library Management System

## Overview
This project is a Library Management System implemented in C++ as part of a technical assessment. The system is designed to handle basic library operations and demonstrate good programming practices, including:
- Object-Oriented Programming (OOP)
- Modular Design
- Test-Driven Development (TDD)
- Use of CMake for build automation
- Integration with Google Test for unit testing
- Automated documentation generation using Doxygen

## Features Implemented
### `Book` Class
The `Book` class represents an individual book in the library. Key features include:
- **Attributes**:
  - Title
  - Author
  - Year of publication
  - Unique ID
  - Quantity (number of copies available)
- **Methods**:
  - Getters for all attributes
  - `borrowBook()`: Decreases the quantity if a copy is available
  - `returnBook()`: Increases the quantity when a book is returned
  - `display()`: Prints the book details in a user-friendly format

### Unit Tests for `Book`
- The `Book` class is tested using Google Test. The following scenarios are covered:
  - Verifying attributes of a created book.
  - Borrowing and returning books, including edge cases where no copies are available.

## Available Scripts
### `setup_environment.sh`
- Automates the installation of development tools, libraries, and VSCode extensions required for the project.
- Includes detailed status reporting to ensure all dependencies are correctly installed.

### `create_project_structure.sh`
- Verifies and creates the necessary folder structure for the project.
- Ensures organizational consistency across the project.

### `setup_git_aliases.sh`
- Registers useful Git aliases to enhance productivity during development.
- Aliases include commands for viewing logs, updating submodules, and syncing repositories.

### `build_project.sh`
- Automates the process of building and testing the project.
- Steps include:
  - Cleaning and setting up the `build/` directory.
  - Running `cmake` to generate build files.
  - Compiling the project using `make`.
  - Executing tests to ensure code functionality.

### `generate_docs.sh`
- Automates the generation of project documentation using Doxygen.
- Steps include:
  - Cleaning up the existing `/docs` directory.
  - Running Doxygen to generate documentation.

## Build and Run Instructions
### Prerequisites
Ensure the following are installed:
- GCC and G++
- CMake (version 3.10 or higher)
- Google Test libraries
- Graphviz

### Building the Project
1. Run the build automation script:
   ```bash
   ./scripts/build_project.sh
   ```

### Running the Tests
The tests are executed automatically as part of the build script. Alternatively, you can run the test executable directly:
```bash
./build/runBookTests
```

### Generating Documentation
Run the `generate_docs.sh` script to generate documentation using Doxygen:
```bash
./scripts/generate_docs.sh
```
